Use Case Descriptions

UC1 — Register Account

ActorGuest
PreconditionUser is not registered
Main Flow1. User fills registration form (username, email, password, name, age, role) → 2. System creates inactive account → 3. System auto-sends OTP email (Django signal) → 4. User verifies email (UC2)
PostconditionAccount created, user is inactive until email verified

UC2 — Verify Email (OTP)

ActorGuest (just registered)
PreconditionUser received 6-digit OTP via email
Main Flow1. User submits email + code → 2. System validates code → 3. System activates account (is_active = True) → 4. Code is deleted
PostconditionUser account is active and can log in

UC3 — Login

ActorGuest
PreconditionUser has an active, verified account
Main Flow1. User sends email + password → 2. Djoser validates credentials → 3. System returns authentication token
PostconditionUser receives auth token for subsequent requests

UC5 — Request Password Reset

ActorGuest
PreconditionUser has a registered account
Main Flow1. User submits email → 2. System generates 6-digit code → 3. System sends styled HTML email with OTP
PostconditionReset code saved in database, email sent to user

UC6 — Reset Password (OTP)

ActorGuest
PreconditionUser received reset code via email
Main Flow1. User submits email + code + new password → 2. System verifies code → 3. System updates password → 4. Code is deleted
PostconditionPassword updated, reset code invalidated

UC8 — Sign Language Recognition (Sign → Text)

ActorGuest / Authenticated User
PreconditionDevice camera is available
Main Flow1. User records 64 frames of sign language → 2. Flutter extracts 114 MediaPipe landmarks per frame → 3. Landmarks sent to /predict/ endpoint → 4. Server preprocesses (dominant hand normalization + motion features) → 5. TFLite model predicts word from 50-word vocabulary → 6. System returns predicted word + confidence
PostconditionUser sees the predicted sign word and confidence score
ExtensionIf save_to_history=true, video uploaded to Cloudinary and prediction saved to DB

UC13 — Speech-to-Sign Translation

ActorGuest / Authenticated User
PreconditionUser has audio to translate
Main Flow1. User records/uploads audio → 2. Server transcribes with OpenAI Whisper → 3. Text normalized (stop words removed, stemmed, and mapped) → 4. System maps words to sign videos on Cloudinary → 5. FFmpeg concatenates videos → 6. Final video uploaded to Cloudinary → 7. User views sign language video
PostconditionUser receives video URL of sign language translation

UC14 — Transcribe Audio via Whisper

ActorSystem
PreconditionSpeech audio is uploaded
Main Flow1. System sends audio file to Whisper → 2. Whisper returns transcribed text → 3. Text is returned to the speech translation pipeline
PostconditionAudio is converted into normalized text for sign generation

UC15 — Generate Sign Video

ActorSystem
PreconditionTranscribed text is available
Main Flow1. System normalizes phrases → 2. It selects sign clip URLs from Cloudinary → 3. FFmpeg concatenates clips into one video → 4. Video is finalized for playback
PostconditionA sign language video is created from the input speech

UC16 — View Sign Video

ActorGuest / Authenticated User
PreconditionSign video has been generated
Main Flow1. System returns Cloudinary video URL → 2. Frontend plays the generated sign video
PostconditionUser watches the speech-to-sign translation

UC17 — Save Translation to History

ActorAuthenticated User
PreconditionUser chooses to save the generated translation
Main Flow1. User requests save → 2. System uploads the generated video to history folder → 3. TranslationHistory record is created with original text, video URL, and timestamp
PostconditionSpeech-to-sign translation is stored in user history

UC25 — Create Event (Admin Only)

ActorAdmin
PreconditionUser is authenticated with role = 'admin'
Main Flow1. Admin submits event data (title, description, image, video, date, location) → 2. Media uploaded to Cloudinary → 3. Event saved to database
PostconditionEvent is visible to all users in the Deaf Hub

UC27 — View Prediction History

ActorAuthenticated User
PreconditionUser has saved sign recognition predictions
Main Flow1. User requests history → 2. System returns SignPredictionHistory records → 3. User reviews past predictions
PostconditionPast sign prediction entries are displayed

UC28 — Delete Prediction Item

ActorAuthenticated User
PreconditionUser selects a saved prediction
Main Flow1. User deletes history entry → 2. System removes that SignPredictionHistory record
PostconditionPrediction entry is removed from history

UC29 — View Translation History

ActorAuthenticated User
PreconditionUser has saved speech-to-sign translations
Main Flow1. User requests translation history → 2. System returns TranslationHistory records → 3. User reviews saved videos and text
PostconditionPast speech-to-sign translations are displayed

UC30 — Delete Translation Item

ActorAuthenticated User
PreconditionUser selects a saved translation
Main Flow1. User deletes translation entry → 2. System removes TranslationHistory record and associated Cloudinary video
PostconditionTranslation entry is removed from history

UC31 — Toggle Favorite

ActorAuthenticated User
PreconditionUser has translation history items
Main Flow1. User toggles favorite status → 2. System updates the TranslationHistory record's is_favorite flag
PostconditionTranslation item is marked as favorite or unmarked
